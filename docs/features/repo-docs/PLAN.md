# Plan: Repo Docs — tiered per-repo context that stays current

**Status**: In Progress
**Created**: 2026-08-10
**Last updated**: 2026-08-10

## Summary

Make every active Areté repo self-describing — what it is, how it's built, how to deploy
and update it — without adding a fifth parallel doc surface and without depending on
Dominick remembering to update anything.

Two halves:

1. **Backfill** the 13 active repos to a known doc floor (`CLAUDE.md` +
   `docs/architecture.md` + new `docs/runbook.md`), generated by a new `/repo-docs` command.
2. **A staleness loop wired into hooks, not slash commands** — the docs announce which code
   paths they describe, and the harness tells you when that code moved.

Success = opening any active repo cold, `CLAUDE.md` orients you in 30 seconds and
`docs/architecture.md` + `docs/runbook.md` answer "how does this work" and "how do I ship
it" without reading source; and a session that changes watched code cannot end without the
staleness being recorded.

## Why not a wiki

Rejected up front, recorded so it doesn't get re-proposed:

- **GitHub Wikis are the wrong artifact.** A wiki is a separate git repo (`repo.wiki.git`),
  not in the checkout. Claude can't read it without cloning, it can't be updated in the same
  PR as the code change, and it never appears in review. The stated goal is "quickly get
  context" — the doc has to be in the working tree for that to be true.
- **The surface already exists and is unused.** `docs/architecture.md` has been scaffolded
  into every repo by `init-claude-setup` since day one. Audit of `~/dev/arete` on 2026-08-10:

  | Surface | Adoption |
  |---|---|
  | `CLAUDE.md` (root or `.claude/`) | 24/44 — `arilearn` and `prg-pricing` are 1-line stubs |
  | `docs/architecture.md` | 6/44, of which `bd-pulse` and `contact-intelligence` are unedited template stubs → **4 real** |
  | `docs/walkthrough/*.md` | 0/44 (skill is 2 commits old) |

  `Project-Tahoe` and `github-actions` are both on the active list in `arete-portfolio` and
  have **no CLAUDE.md and no architecture doc at all**.

  A fifth doc type does not fix 4/44. Adding one violates Reuse Before Adding.
- **"Keep docs updated" as a CLAUDE.md bullet will not work**, per this repo's own rule:
  *"Enforcement beats prose."* 4/44 is that principle proving itself.

## Why enforcement goes in hooks, not `/end-session`

Dominick does not run `/end-session` reliably. This repo already hit that exact wall and
already solved it — `global/hooks/session-end.js:8`:

> *"This used to be wired to `Stop`... That is why the session log filled with stubs and why
> 'run /end-session religiously' became a documented gotcha"*

The fix then was to move the work out of the slash command and into a hook that fires
whether or not the command is typed. Doc staleness gets the same treatment. Anything gated
on remembering a command is not enforcement.

## Repo tiers — not all 44

21 archived, 10 dormant, 13 active. Documenting a dead repo is worse than leaving it blank:
`arete-portfolio` already warns that *"several dead repos have an active successor, and the
dead one is still a plausible-looking destination."* A polished architecture doc on a corpse
makes that trap more convincing.

- **Tier 1 — full set** (`CLAUDE.md` + `architecture.md` + `runbook.md`): the 13 active repos.
- **Tier 2 — `CLAUDE.md` only**: the 10 dormant repos. Enough to orient, no upkeep.
- **Tier 3 — one line**: the 21 archived. `> Archived <date>. Superseded by <repo>.` Highest
  value-per-byte doc in the portfolio.

**This plan covers Tier 1 only.** Tiers 2–3 are follow-on work.

## Design

### Doc frontmatter contract

Every maintained doc declares what it describes:

```yaml
---
doc: architecture          # architecture | runbook
verified: 2026-08-10       # last time a human confirmed it accurate
watches:                   # globs whose change invalidates this doc
  - lib/**
  - config/**
---
```

`watches` is the whole mechanism. Without it, staleness detection is guesswork.

### The loop

1. `track-changes.js` (PostToolUse, **already exists, unchanged**) appends every edited path
   to `.claude/memory/dirty-files`.
2. `doc-staleness.js` on **SessionEnd** reads `dirty-files`, parses `watches:` from
   `CLAUDE.md` and `docs/*.md`, intersects, writes `.claude/memory/stale-docs`. Fires whether
   or not `/end-session` was run.
3. `doc-staleness.js` on **SessionStart** reads `stale-docs` and returns it as
   `additionalContext`, so the next session opens already knowing which docs the last one
   invalidated — at the moment Claude can actually act on it.
4. `/repo-docs` refreshes a doc, bumps `verified:`, and clears its entry from `stale-docs`.

SessionEnd can only *record* — the session is over and Claude isn't there. SessionStart is
where it becomes actionable. Both halves are required; neither works alone.

### Deliberately deferred: the commit-time gate

A `git commit` gate in `guard-bash.js` is the version that can't be skipped — that's the
chokepoint. It's deferred to Phase 4 and **optional**, because a prompt on every commit
while a doc is stale is the version that gets disabled the first time it fires on a typo
fix. Ship the SessionStart surfacing first; escalate only if docs still slip.

## Implementation Steps

### Phase 0 — Validate the premise before building anything

The 4/44 number is evidence that nobody maintains these docs. It is **not** evidence that
enforcement is the fix — it may be that nobody ever needed them. Measure first.

- [ ] Step 1 — For the 4 real `architecture.md` files (`areteos`, `arete-terraform-infrastructure`,
  `microsoft-entra-terraform-infrastructure`, `infisical`), compare last-touched date against
  churn in the paths they describe:
  `git log -1 --format=%ai -- docs/architecture.md` vs
  `git log --since=<that date> --oneline -- lib/ config/ | wc -l`.
  Record the numbers in `EXECUTION_LOG.md`.
- [ ] Step 2 — Spot-check accuracy: read each of the 4 docs and verify 3 concrete claims each
  against current code. Count how many are now wrong.
- [ ] **Gate:** if the 4 docs are broadly accurate and low-churn, the staleness loop is
  solving a problem that doesn't exist — stop, do the backfill only, and skip Phases 2–4.
  If they're stale and wrong, Phases 2–4 are justified. Report the numbers and decide.

### Phase 1 — Template and contract

- [ ] Step 3 — Add `watches:`/`verified:` frontmatter to `project-template/docs/architecture.md`.
  Keep the existing body sections (Overview, Key Design Decisions, Data Flow, External
  Dependencies, Known Limitations). Add a commented `watches:` example per stack.
- [ ] Step 4 — Create `project-template/docs/runbook.md`. Sections: How to run locally;
  Environments (dev/prod, URLs, accounts); Secrets (Infisical path, how injected); Deploy
  (trigger, what runs, how long, how to tell it worked); Rollback (exact commands);
  Scheduled work (crons, Oban queues); On-call gotchas. Same frontmatter contract.
- [ ] Step 5 — Update `project-template/.claude/CLAUDE.md` Important Paths comment to list
  `docs/runbook.md` alongside `docs/features/` and `docs/solutions/`.
- [ ] **Note:** `install-claude-setup --force` also copies `project-template/` into every path
  in `~/.claude/.projects`. Adding `runbook.md` will propagate to all of them. Use
  `--skip-projects` if that isn't wanted yet.

### Phase 2 — The `/repo-docs` command

- [ ] Step 6 — Create `global/skills/repo-docs/SKILL.md` with `disable-model-invocation: true`,
  `argument-hint: "[architecture | runbook | both (default)] [--refresh]"`.
  Directory name is the slash command — check `/repo-docs` doesn't shadow a built-in.
  - Recon: spawn **one** `Explore` agent, reusing the per-stack entry-point recipes in
    `global/skills/walkthrough/references/recon.md`. Do not duplicate those recipes.
  - Derive `watches:` from what recon found load-bearing (spine + high-churn paths), not
    from a hardcoded per-stack guess.
  - `--refresh` mode: don't clobber. Keep claims that still hold, fix moved anchors, bump
    `verified:`, list what changed — same non-destructive contract as `/walkthrough` Phase 4.
  - Gate on a proposed outline before writing, same as `/walkthrough` Phase 2.
  - Runbook facts must come from real files (CI workflows, compose files, `.tf`, Infisical
    paths) or be written as `**unknown**`. Never guess a deploy procedure — a wrong runbook
    is worse than none.
- [ ] Step 7 — Add one line to `global/CLAUDE.md` Standard Workflow:
  `**Document a repo**: /repo-docs — writes docs/architecture.md + docs/runbook.md`, plus a
  rule distinguishing it from `/walkthrough` (walkthrough teaches a human one subsystem;
  repo-docs writes the durable repo-level reference).

### Phase 3 — The staleness loop

- [ ] Step 8 — Create `global/hooks/doc-staleness.js`. Node ≥16, exits 0 silently otherwise,
  **fails open always** — a broken hook must never wedge the session (same contract as
  `guard-bash.js`). Two modes via argv: `record` and `surface`.
  - `record`: read `.claude/memory/dirty-files`; glob `CLAUDE.md`, `.claude/CLAUDE.md`,
    `docs/*.md`; parse `watches:` frontmatter; intersect; write `.claude/memory/stale-docs`
    as `<doc path>\t<matched paths>`. No-op if no `.claude/` dir or `dirty-files` is empty.
    Skip `.claude/memory/**` (same exclusion `track-changes.js` already makes).
  - `surface`: read `stale-docs`, emit `additionalContext` JSON naming the stale docs and
    what changed under them. Silent when the file is empty or absent.
- [ ] Step 9 — Wire into `global/settings.json`:
  - Append to the existing `SessionEnd` array: `node ~/.claude/hooks/doc-staleness.js record`.
    Order after `session-end.js` — that one exits early on empty `dirty-files` and both read it.
  - Add a new matcher-less `SessionStart` entry: `node ~/.claude/hooks/doc-staleness.js surface`.
    The existing SessionStart entry has `matcher: "compact"` and must be left alone.
- [ ] Step 10 — Test the hooks. Extend `tests/` following `tests/test-guard-bash.js`:
  glob matching, missing frontmatter, malformed YAML, absent `dirty-files`, absent `.claude/`,
  and the memory-dir exclusion. Assert fail-open on every error path.
- [ ] Step 11 — Dogfood in `claude-setup` itself for one week before touching other repos.
  This repo is Tier 1 and edits here are live, so it's the honest test bed.

### Phase 4 — Commit gate (OPTIONAL, only if docs still slip)

- [ ] Step 12 — Only if Phase 3 dogfooding shows docs going stale and staying stale: add a
  non-blocking `ask` on `git commit` to `guard-bash.js` when a Tier-1 `architecture.md` or
  `runbook.md` is stale. Fire **once per session** via a marker file. Never block. Revisit
  after two weeks and rip it out if it's just noise.

- [ ] Step 16 — `areteos-py`, `arilearn-phx`: `/repo-docs`. Both have substantial CLAUDE.md

## Risks / Open Questions

- **Phase 0 may kill Phases 2–4.** That's the point of putting it first. Do not skip it.
- **`watches:` globs will be wrong at first.** Too broad → every session flags every doc →
  noise → you disable it. Start narrow (the spine only), widen when a real drift is missed.
- **Generated docs can be confidently wrong.** Runbooks especially. `**unknown**` is a valid
  and preferred output — mirror the `arete-portfolio` standard of marking rather than guessing.
- **Always-loaded context budget.** `CLAUDE.md` files at 293L and 317L already load every
  session in those repos. This plan should *shrink* them by relocating architecture prose,
  not add to them.
- **Open:** does `additionalContext` from a matcher-less SessionStart hook actually surface
  reliably in the current Claude Code build? Verify in Step 8 before building on it; fall back
  to the Phase 4 commit gate as primary if not.
- **Open:** Tier 2/3 rollout (dormant + archived one-liners) is deliberately out of scope.
  The archived one-liners are cheap and high-value — worth a separate small pass.
